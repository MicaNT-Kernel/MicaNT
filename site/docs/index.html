Building MicaNT from Source

MicaNT compiles cleanly using modern LLVM/Clang toolchains with standard C++23 flags. There are zero proprietary SDK dependencies; the build pulls from MIT-licensed DirectX-Headers and Microsoft win32metadata projections.

Prerequisites

Ensure you have the following toolchain installed:

# Required Toolchain
LLVM / Clang 18.0+ (clang-cl or clang++)
CMake 3.28+
Ninja 1.11+
LLD Linker (lld-link or ld.lld)
MinGW-w64 UCRT (for Windows/UEFI PE image target)

Compilation

# Clone the sovereign repository
git clone https://github.com/MicaNT-Kernel/MicaNT.git
cd MicaNT

# Configure Release build with Ninja
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release

# Build the complete kernel, tests, and userland utilities
cmake --build build --config Release

QEMU Bare-Metal UEFI Emulation

MicaNT boots directly via UEFI GOP into a raw 3840x2160 or 1920x1080 linear framebuffer. Test bare-metal boot behavior in QEMU: 

qemu-system-x86_64 \
  -drive file=micant_os.img,format=raw \
  -m 4G \
  -smp 4 \
  -bios /usr/share/ovmf/OVMF.fd \
  -vga std \
  -device nec-usb-xhci,id=xhci \
  -device usb-mouse,bus=xhci.0 \
  -device usb-kbd,bus=xhci.0 \
  -serial stdio

The 4-Ring Sovereign Isolation Model

In 1996, Windows NT 4.0 moved graphics (GDI/USER) directly into Ring 0 (win32k.sys) to win synthetic desktop drawing benchmarks, introducing thousands of kernel security attack surfaces. MicaNT permanently restores architectural purity via 4 distinct rings of hardware-enforced isolation:

Ring 0: Microkernel Executive
PML4 memory manager, Object Manager, scheduler spinlocks, and IRQL trap dispatcher.
Ring 1: Real-Time Hardware
PrismX Direct3D 12 WDDM display drivers and WaveRT audio engines with sub-millisecond buffers.
Ring 2: System Accelerators
NVMe DirectStorage DMA engine (14.8 GB/s) and sub-pixel GPU font glyph rasterizers.
Ring 3: Userland Isolation
Win32 subsystems, ConHost 2.0 shell, native 64-bit PE applications, and zero-telemetry daemons.

Fast System Call Dispatcher & KUSER_SHARED_DATA

MicaNT programs the AMD64 LSTAR Model-Specific Register (0xC0000082) with the address of KiSystemCall64. High-frequency queries (such as system tick count, interrupt time, and processor features) are fulfilled completely in userland without context switches: 

// Userland zero-syscall time acquisition via KUSER_SHARED_DATA
#define MM_SHARED_USER_DATA_VA 0x7FFE0000
auto pKUser = reinterpret_cast<KUSER_SHARED_DATA*>(MM_SHARED_USER_DATA_VA);

// Read synchronized 64-bit interrupt time without trapping to Ring 0:
uint64_t interruptTime = pKUser->InterruptTime.QuadPart; // 0 Syscalls (0 ns latency)

The Object Manager (ob/)

Every file, section, process, thread, device, directory, and event is a reference-counted kernel object governed by an atomic handle table and security descriptors: 

// Named Object Hierarchy Namespace:
\
├── DosDevices\          (C:, D:, COM1, GLOBALROOT)
├── KnownDlls\           (ntdll.dll, kernel32.dll, user32.dll)
├── Device\              (HarddiskVolume1, XhciController0, PrismGPU0)
├── Driver\              (prismx.sys, xhci.sys, aehd.sys, titan_zfs.sys)
├── ThemeApiPort         (ALPC endpoint for Ring 2 font & theme rasterization)
└── RPC Control\         (epmapper, lsass RPC rendezvous ports)
